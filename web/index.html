01 / WHY

Alertmanager 只有 silencing / inhibition 两板斧

alerta、karma 又偏重。生产环境日均千级告警最缺的六件事，alert-sift 用一个单进程补齐——源自生产实战沉淀，替代「Alertmanager + 一堆脚本」的松散组合。

生产痛点alert-sift 的解法
同一故障风暴刷屏几十条
L2 指纹去重 + L5 窗口聚合，风暴折叠为计数卡
维护窗口静默要手动改配置
L3 静默走 YAML / API，时间窗 + 标签匹配动态增删
父告警 firing，子告警照推
L4 抑制：主机宕机压制其上全部子告警，不再连带刷 20 条
机器人被限流 45009 打满配额
per-robot 令牌桶限流，P0 不节流保可达
P0-P4 不分级全量推送
L6 分级 + 路由树，P0 自动双发高优通知组
让 AI 改配置，怕删库
guard 护栏：RBAC + 高危审批 + 审计 + dry_run 默认

03 / GUARD

AI 运维护栏 —— 核心差异化

内置 MCP Server（19 个工具），AI 助手可直达「查活跃告警 → 建静默 → 改规则」全流程；guard.py 为 AI 写操作上三层锁，高危步骤自动拦截等人审批。

01

RBAC 角色隔离

configs/guard.yaml

ai 角色仅放行读类与预览动作，human 全开。角色 → 动作清单一个 YAML 一目了然，越权调用直接拒绝。

02

高危审批闭环

request_approval → approve

静默 / 抑制 / 规则 / 通知路由的写操作须先申请，人 approve 后才放行，审批带有效期，超时自动作废。

AI 发起人工审批放行执行
03

审计 + 回滚

actor / action / params

每次写操作留完整证据链；dry_run 预览默认开，改前先看差异；.bak 自动备份，一键回滚。

04 / QUICKSTART

单进程 + SQLite，零外部依赖，5 分钟跑通

1

安装并启动

REST 控制面 + 通知一体，机器人 key 走 ${WECOM_BOT_*} 环境变量，禁止明文入仓。

2

指向本服务

vmalert / Alertmanager 改一行 notifier 指向即可，webhook v2 协议兼容。

3

（可选）启动 AI 护栏

MCP Server 独立进程 :9998，对接 WorkBuddy / Claude Desktop 等任意 MCP 客户端。

4

管理 API 与文档

启动后访问 /docs 查看全量 OpenAPI：告警查询、静默 CRUD、规则热加载、历史导出。

bash — alert-sift 
# 1. 安装并启动（REST 控制面 + 通知）
pip install -r requirements.txt
export WECOM_BOT_APP="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<你的key>"
uvicorn app.main:app --host 0.0.0.0 --port 9999

# 2. vmalert / Alertmanager 指过来（webhook v2 兼容）
vmalert -notifier.url=http://alert-sift:9999

# 3.（可选）AI 护栏：MCP Server 独立进程
pip install "alert-sift[mcp]"
python app/mcp_server.py --transport http --port 9998

环境变量 ALERT_SIFT_CONFIG 指定主配置路径；Docker 一键容器化，官方 Dockerfile 即 build 即用。
